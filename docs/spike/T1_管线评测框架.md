# T-1 抽象管线 Spike 评测框架（go/no-go）

> 目标：在投入全量 VLM 前，用最小 spike 判定"端侧事件闸门 + 云 VLM 细描"这条
> 管线**值不值得做**。go = 继续投全量；no-go = 退回纯端侧 YOLO（省钱）。
> 代码：`vision/event_trigger.py`（5 类事件闸门）+ `vision/perception_service.py`（接线）。
> 自检：`python vision/event_trigger.py --self-test`（7 项全过）。

## 管线架构（分层不重复花钱）

```
FrameSource.read()  →  YOLO(frame)  →  describe_frame()  [端侧，每帧，免费]
                                              ↓
                                  帧记录 world_perception.json
                                              ↓
                                  summarize(window)  [端侧，每 30min，免费]
                                              ↓
                                  events（new_group / scene_change）
                                              ↓
                                  EventTrigger.enrich()  [云 VLM，只在 5 类事件，花钱]
                                              ↓
                                  富化事件（vlm_description）→ proactive_signal 消费
```

**核心原则：平时 0 次 VLM。** 端侧 YOLO 每帧粗筛（7 组，免费），只有 5 类事件
（新物体首现/场景切换/找物查询/跌倒疑似/老人"记一下"）才调云 VLM 细描。
其余帧零 VLM 调用——这是省钱的关键。

## 5 类事件闸门 + 冷却

| 事件 | 触发条件 | 冷却 | VLM prompt 目标 |
|---|---|---|---|
| new_object_first_seen | 端侧 YOLO 没见过的组 | 1h | 细描新物体是什么、位置（家具级） |
| scene_change | 主场景变了 | 2h | 细描新场景里有什么 |
| find_object_query | 老人问"我的X在哪" | 5min | 细描有没有这个物体、在哪 |
| fall_suspected | 连续 3 帧有人→突然无人 | 1min | 细描人的姿态和位置（确认跌倒） |
| elder_remember | 老人说"记一下" | 10min | 细描画面里有什么（人/物/事/位置） |

## go/no-go 判定标准

**go（继续投全量）** 需同时满足：
1. **调用次数可控**：24h 模拟跑，VLM 调用次数 ≤ 30 次/天（5 类事件 + 冷却后）。
   超出说明闸门太松，要收紧冷却。
2. **命中率 ≥ 60%**：VLM 细描的事件里，≥60% 对 proactive_signal 产出了"值得说"的话
   （不是废话）。低于 60% 说明 VLM 细描质量不够，退回纯端侧。
3. **降级率 ≤ 10%**：VLM 不可用/失败导致的降级 ≤10%。高于 10% 说明 VLM 依赖太重，
   要考虑纯端侧方案。
4. **跌倒疑似零漏报**：跌倒疑似事件 100% 触发 VLM（安全类不省钱）。

**no-go（退回纯端侧 YOLO）** 触发任一条：
- 调用次数 > 50 次/天（闸门太松，成本不可控）。
- 命中率 < 40%（VLM 细描质量不够，不如纯端侧）。
- 降级率 > 30%（VLM 依赖太重，可靠性不够）。

## 评测方法

1. **模拟跑**：`python vision/perception_service.py --interval 2 --summary-every 60 --duration 1`
   （1 小时模拟，summary-every 60s 加速事件密度）。
2. **统计 VLM 调用**：读 `vision/data/vlm_calls.jsonl`（每次调用一条），统计次数/类型/降级率。
3. **统计命中率**：人工标注 VLM 细描事件里"值得说"的比例（spike 阶段人工标，全量阶段自动化）。
4. **判定**：对照上面的 go/no-go 标准，出结论（go / no-go + 理由）。

## 诚实降级（绝不静默）

- VLM 不可用（vlm_call=None）→ `vlm_called=False, vlm_reason=no_vlm`，用 YOLO 粗结果。
- VLM 失败（抛异常）→ `vlm_called=False, vlm_reason=error: ...`，绝不静默。
- 降级事件照样进 proactive_signal（只是没有 VLM 细描，用 YOLO 粗结果兜底）。

## 与 T-2 契约对齐

VLM 细描 prompt 要求"位置到家具级"（如"床头柜上"），符合 T-2 的 11 字段契约
（location ≥ 家具级）。VLM 富化事件经 `memory_system.ingest_visual_event()`
喂给 `find_object()` 的 graph 层（source="visual"，0 行改 memory_system.py）。
