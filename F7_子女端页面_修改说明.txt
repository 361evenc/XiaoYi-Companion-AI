F-7 子女端页面 —— 修改说明
============================================================
日期：2026-11-08
任务卡：F-7（前端 / P1 / 前置 B-9 只读 API）

一、修改原因
------------------------------------------------------------
子女端是"远程安心"的落点，也是子女付费动机唯一能接住的界面。
它要同时满足三件事：
  1) 子女看得到但看不了全部：只给健康异常摘要 + 情绪趋势 + 购药待办，
     绝不展示完整聊天记录（监控感 = 老人拒绝）；
  2) 老人始终知道：安心开关默认开，首次激活用大字 + 语音明确告知
     "孩子能看到您的吃药和心情概况，看不到聊天内容"；老人/子女都能独立关；
  3) 平时不空白：每天一句"今日概况"，不做实时流，避免子女把它当监控盯着看。

前置缺口（重要，先说明）：
  - B-9（子女只读 API）不在本仓库 → 本次按任务卡口径补了最小只读实现
    /api/child/*，数据源全是现有只读数据（提醒 / 情绪日志 / 跌倒状态）；
    B-9 落地后替换数据源即可，前端字段与隐私口径不变。
  - T-4（购药闭环）不在本仓库 → 本次只做最小闭环：从含"药"的提醒派生待办，
    回执只记录"已处理"并给老人生成通知；不改提醒、不改药量、不下单。
  - 没有系统推送通道 → "今日概况"改为页面内每天生成/缓存一次（不做 App 推送）。

二、修改内容（按文件）
------------------------------------------------------------
1. backend/services/child_service.py（新增）
   - 持久化：项目根 child_portal.json（运行时生成，单机单人；验证后已删除，
     首次启动即为默认值），含 consent / daily / receipts / notices 四块。
   - 安心开关：默认开（_default_state 里 enabled=True），GET/POST 都能改；
     关闭后 summary 只回 {ok, enabled:false, closed_text:"已关闭"}，
     不带 today/health/emotion/purchase/privacy —— 关闭即隐藏，不泄露。
   - 隐私边界写死在服务层：
       · 本模块没有任何读取会话/聊天记录的能力（不 import、不读 conversations.json）；
       · 返回体只有概况字段；CANNOT_SEE 固定含"聊天内容"；
       · 只读提醒（reminder_service.list）、情绪日志（engine.load_emotion_log）、
         跌倒状态（fall_guard.guard.status）；不写老人记忆。
   - 今日概况：一句话（吃药 / 心情 / 聊了N次），按自然日缓存（daily.date 命中直接返回），
     每天只生成一次。
   - 情绪趋势两种视图：子女版=按天聚合点（分数/主导情绪/次数，不含原话）；
     老人版=复用现有 memory_service.emotion_chart() 生成的心情曲线图，不另画一套。
   - 健康异常摘要（行为层）：吃药提醒未确认 / 可能摔倒（asking、escalated）/
     当天情绪低落；无异常给"今天没发现异常"，不做医疗判断。
   - 购药待办：含"药"的 awaiting + pending 提醒；回执只写 receipts 并生成一条
     老人通知（"您孩子给您买了药：…，吃不吃、什么时候吃，您自己拿主意。"），
     绝不调用提醒的 done/cancel/confirm —— 子女只建议，老人始终知情。
   - 首次告知话术 NOTICE_TEXT 集中在服务端，老人端与子女端引用同一句。

2. backend/api/child_api.py（新增）
   - 路由白名单（没有会话/聊天路由，也没有 DELETE）：
       GET  /api/child/summary
       GET  /api/child/consent
       POST /api/child/consent
       POST /api/child/consent/notified
       POST /api/child/purchase/{rid}/receipt
       GET  /api/child/notices
       POST /api/child/notices/{nid}/ack

3. backend/main.py
   - import 并 include_router(child_api.router)，一行挂载，不影响原有路由。

4. frontend/src/views/ChildHome.vue（新增）
   - 子女端一页（/child）：今日概况、健康异常摘要、情绪趋势（子女版/老人版切换）、
     购药待办（展示 + "我来处理"回执 + "已告诉老人"）、隐私边界（能看到/看不到）、
     "关掉「子女远程安心」"按钮、首次使用给老人念的告知卡（可 TTS 播放）。
   - 关闭时整块只读区换成"已关闭"卡片 + "重新打开"，不显示任何概况。
   - 大字设计（正文 ≥18px、按钮 ≥48px、概况 24px），沿用 .card/.btn/.topbar 设计系统。

5. frontend/src/views/Welcome.vue
   - 底部新增角色入口"👨‍👩‍👧 我是子女，看看老人的近况" → /child；
     老人侧栏（SidebarCards.vue）刻意不放，避免老人误入。

6. frontend/src/views/Privacy.vue
   - 新增"孩子能看到什么"卡：写明能看到吃药/心情概况、看不到聊天内容，
     老人可独立关/开安心开关；并说明"关掉只是孩子看不到，您该提醒还提醒"。

7. frontend/src/views/Chat.vue
   - 首次进入（consent.enabled && !notified）显示"跟您说个事儿"大字告知，
     同步 TTS 念同一句话；两个按钮：
       "我知道了" → 标记已告知；
       "不让看" → 关掉安心开关 + 标记已告知。
   - 进入时拉 /api/child/notices：未读的购药回执通知作为小忆消息播报一次
     （TTS + 字幕）并 ack，避免重复打扰。

8. frontend/src/api/index.js
   - 新增 childSummary / childConsent / setChildConsent / childNotified /
     childPurchaseReceipt / childNotices / childNoticeAck；
     子女端封装里没有任何会话接口（前端拿不到，后端也不提供）。

9. frontend/src/router/index.js
   - 新增 /child（ChildHome），同一 PWA、角色切换，不单独做 App（O-10 写死形态）。

10. 测试
   - test_child_privacy.py（新增，项目根）：任务卡要求的 5 条权限用例，
     使用假数据源、临时状态文件，不拉起引擎、不碰真实提醒/情绪数据：
       1) 摘要无聊天字段（含递归键检查 + 服务源码无会话能力）
       2) 无会话路由（/api/child 路径白名单）
       3) 关闭即隐藏（默认开、关后只剩 enabled=false）
       4) 无老人记忆写入口（无 DELETE、POST 仅 4 条、源码无 wipe/forget/提醒写操作）
       5) 回执不改提醒且生成通知（提醒快照比对 + 通知 + ack + 找不到要诚实地拒绝）
     支持 --runner 名字，输出保留"第二人复核签字"行。
   - frontend/tests/f7_guardrails.mjs（新增）：5 组固定检查（角色入口/默认开/已关闭、
     无聊天请求、情绪双视图、每日概况缓存、购药三件套 + 首次告知 + 老人可关）。

三、技术边界（这次明确不做）
------------------------------------------------------------
- 不做完整聊天记录：子女端没有入口，后端也没有任何会话读取能力（不是前端藏起来）；
- 不做系统推送：今日概况只在子女打开页面时按天生成/缓存一次，不实时、不推送；
- 不做下单/支付：购药只做"待办 + 回执 + 通知老人"三件套，不接药房、不改药量；
- 不改提醒状态：回执只写 receipts，提醒的完成/取消仍只在老人侧（或原有提醒链路）；
- 不做账号体系/鉴权：沿用单机单人、无鉴权架构；多设备远程查看需要 B-9 + 鉴权才能做；
- 不做多老人/多子女绑定：当前只有一位老人、一个安心开关。

五、需要人工 / 第二人执行的验收项（不是代码能自证的）

   跑法：python test_child_privacy.py --runner 第二人姓名
   然后把输出与签字行填进验收记录；本次自测已通过，但不作为验收最终结论。
2) 首次激活告知话术可用性：真人在测试环境走一遍"进入聊天 → 听语音 → 点我知道了/不让看"，
   确认老人能听懂"能看到吃药和心情概况、看不到聊天内容"，且没有误解为"被监控聊天"。
3) 关闭影响范围逐项验证：关掉后
     - 子女端只读区显示"已关闭"（已验证）；
     - 老人端提醒、聊天、录制、找物等功能不受影响（代码上开关只 gate summary，需实机逐项过）；
     - 再打开后概况恢复（已验证）。
4) 购药三件套真实链路：在测试环境造一条含"药"的提醒 → 子女端"我来处理" →
   老人端进入聊天收到"您孩子给您买了药"播报；确认提醒本身没被改、药量没被改。
   （本次用假数据源覆盖了服务层口径，真实提醒链路需人工走一遍）
5) "今日概况每天 1 次"：跨自然日验证（今天打开后文案固定；第二天重新生成）。

六、回滚方式
------------------------------------------------------------
- 前端：删除 /child 路由、ChildHome.vue、Welcome.vue 入口、Privacy.vue 安心卡、
  Chat.vue 的 careNotice/pollChildNotices 分支、api 中 child* 七个方法即恢复原状；
- 后端：main.py 去掉 include_router(child_api.router)；child_api.py / child_service.py 可整体删除；
- 数据：child_portal.json 为运行时文件，删除即回到"默认开、未告知"的初始状态；
- 无数据库迁移，无记忆结构变更，回滚不影响老人已有记忆、情绪日志与提醒。
