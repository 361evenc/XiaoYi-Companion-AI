人物建档聊天链路 —— 修改说明
======================================

修改时间：2026-11-08
任务背景：F-4 时间线页的"人"维度依赖人物档案，但 memory_system 里只有
add_person_profile / remove_person_profile，生产聊天链路没有调用点 ——
老人说"这是我孙子豆豆"不会被记录，时间线永远走 fallback_visitor。
本次把"老人主动陈述 → 小忆复述确认 → 老人说对 → 写入档案"接到聊天里。

一、修改原因
------------------------
F-4 口径写死：建档唯一路径 = 老人自己主动说"这是我XX" + 小忆确认；AI 不猜；子女端不建档；
档案字段 = 姓名 + 称谓（不存人脸特征）；老人说"别叫了"可删，删后退回三类。
原链路缺失，导致：
  - 老人说了"这是我孙子豆豆"，小忆当普通聊天，不建档；
  - 时间线人物维度只能显示"有客人来过"。

二、修改内容（2 个文件）
------------------------
1. memory_system.py
   a. 新增人物建档正则（模块级，紧跟 OLD_VALUE_Q_RE 之后）：
      - _PROFILE_INTRO_RE：只认"这是/那是我（家/的）REL（名字）"，整句锚定；
      - _PROFILE_CALL_RE："我（家/的）REL（，叫）NAME"（含"这是…，叫…"变体）；
      - _PROFILE_REMOVE_RE："以后别叫 NAME 了 / 别再提 NAME 啦"（不带名字的"别叫了"不接管）；
      - _PROFILE_NOT_NAME：名字位置后面是"的/照/在/刚/考上/了/吧…"一律不当名字（重要：防误猜）；
      - _profile_name_from_reply：老人报名字时去前缀（叫/是/他）、去语气词、截断问句。
      REL 只含长辈/晚辈常见亲属 20 个（孙子/孙女/外孙/外孙女/儿子/女儿/儿媳/女婿/
      老伴/老伴儿/爱人/爸爸/妈妈/哥哥/弟弟/姐姐/妹妹/儿媳妇/外孙子）。
   b. MemoryBank 新增状态 pending_profile（待确认档案：rel/name/quote/ts/stage），
      纳入 __init__ / _load / _save —— 重启后未答完的确认不会丢，且沿用 CONFIRM_TTL 超时作废。
   c. 新增 handle_person_profile_chat(text, call, now)：确定性流程，不调模型：
      - 有 pending：
        · stage=ask_name：老人报名字 → 复述确认"X 是您的孙子，对吧？"；
        · stage=confirm：借 classify_confirm_reply 判定
          "对/是" → add_person_profile；"不对，叫毛毛" → 改名后再确认；
          说别的 → 返回 None，不抢话，pending 留着等老人回来答；
      - 无 pending：
        · "别叫豆豆了" → remove_person_profile → "好，往后我不提豆豆了"（没有就说没有，不编造）；
        · "这是我孙子豆豆" → 先复述确认，**不直接写**；
        · "这是我孙子"（没名字）→ "您孙子叫什么名字呀？"，问到名字再确认。
      - 永远不猜：名字没听清 / 句式不像陈述 / 超过 40 字，一律返回 None 放行正常聊天。

2. app.py（chat_response，插在"记忆主动确认"之前）
       prof_reply = memory_bank.handle_person_profile_chat(
           user_input, user_memory["call_name"])
   命中则保存历史并直接返回该回复（不调大模型、不写记忆事实）。
   放在事实确认之前的原因：建档的"对/不对"不能被 resolve_confirm_reply 先接走。

三、明确未做（按任务卡边界）
------------------------
1. 没有在子女端/设置页加任何"新建人物"入口（零子女配置原则）；
2. 不存人脸特征，不改造人脸识别；档案只用于"对话关联 + 检索时显示名字"；
3. 不新增前端界面（聊天页原样接收 /api/chat 回复即可）；F-4 时间线页自动受益：
   检索人物时 resolved.kind=profile，页面显示"这是您说过的「豆豆」"。

四、验证结果
------------------------
1. 单元测试（临时脚本，已删除）14 项全部 PASS：
   - "这是我孙子豆豆" → 先问"对吧？"，确认前档案为空；
   - "对" → 写入 {name:豆豆, calls:[孙子], quotes:[原话]}；
   - by=person 查"豆豆" → resolved.kind=profile、name=豆豆；
   - 中间说别的 → 不接管、pending 保留、随后"对"仍能闭环；
   - "不对，叫豆豆" → 改名后再确认，不写错名字；
   - "这是我孙女" → 先问名字，报"小美"→确认→写入；
   - 不猜：这是我孙子的照片 / 这是我孙子考上大学了 / 我孙子叫啥来着 / 我孙子在睡觉 → 全部 None；
   - 超时（>CONFIRM_TTL）→ 不再接管、不写档案；
   - "以后别叫豆豆了" → 删除成功并回话；"别叫了"（无名字）→ 不接管、不误删；
   - _save/_load 后档案与待确认状态仍在。
2. HTTP 端到端（真实 /api/chat，后端 8010）：
   - 第一轮"这是我孙子豆豆" → 回复"我记下了：豆豆 是您的孙子，对吧？"；
   - 第二轮"对" → 回复"好嘞张奶奶，我记住了：豆豆 是您的孙子。以后您一提豆豆，
     我就知道是自家人了。"；
   - GET /api/memory/search?by=person&q=豆豆 → {"kind":"profile","name":"豆豆"}；
   - memory_bank.json 中 person_profiles = [{name:豆豆, calls:[孙子], quotes:[这是我孙子豆豆]}]。
   测试后已还原 memory_bank.json / conversations.json / emotion_log.json / user_memory.json，
   不残留测试档案或测试对话。

五、已知限制
------------------------
1. 只覆盖两种明确句式（"这是我+亲属称谓(+名字)"、"我+亲属称谓+叫+名字"）；
   更口语的说法（"豆豆是我孙子""我那个孙子叫豆豆"）暂不建档 —— 宁可少建不可建错。
2. 亲属称谓是固定 20 个词表，不认识的称谓（如"干儿子""老邻居"）不建档。
3. "别叫了"单独一句不接管（可能是"别打电话了"），必须带名字才删档案。
4. 建档只走聊天文本；语音经由 ASR 后同样进入 /api/chat，无需额外改造，但 ASR 错字
   可能导致名字存错（可用"不对，叫…"当场纠正）。
5. 删除档案只删档案，不删与之关联的历史记忆文本（避免连带丢老人记忆）。

六、如何复核
------------------------
1. python run.py，进聊天页；
2. 说"这是我孙子豆豆" → 小忆复述确认；说"对" → 档案建立；
3. 打开家庭时间线 → 人 → 输入"豆豆" → 出现"这是您说过的「豆豆」"；
4. 说"以后别叫豆豆了" → 档案删除，时间线退回"有客人来过"。
