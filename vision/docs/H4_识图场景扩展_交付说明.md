## 二、两个场景的关键设计（为什么这么做）

### 2.1 老照片：四个条件同时成立才敢问一句

```
允许开口问"这是您X吧"的条件（and）：
  ① 画面接近黑白/褪色（平均彩度 < 32）  —— 排除当天的生活照
  ② 画面里只有 1 个人                     —— 合影里认错人最伤人
  ③ 有候选且候选分 ≥ 0.5                  —— 来自 B-5 的 known_people
  ④ VLM 描述里提到的关系与候选关系不矛盾
任一不满足 → 直接说"我认不太准"
```

- 候选分怎么来：关系词命中 +0.35、老照片且有出生年 +0.2。**不看脸**——MVP 没有人脸库，硬做人脸比对等于编造"匹配度 87%"，比不认更糟。
- 结果里 `certain` 在两处为 `true`：① 画面里确实没人（这是确定结论）② 从没猜过。**猜出来的永远是 `certain: false` + `needs_confirm: true`。**

### 2.2 说明书：只读，不判断

| 说 | 不说 |
|---|---|
| "这个是阿托伐他汀钙片。" | "这个药适合您。" |
| "包装上写的用法是：口服 每日一次 每次20mg。" | "您一天吃一次就行。" |
| "这是处方药，要听医生或药师的。" | "您可以吃这个。" |
| "有几行字太小，我没看清，以包装和药师说的为准。" | "没什么副作用。" |

**剂量只回显原文，绝不加工。** OCR 会把 `1 片` 读成 `l 片`、`0.5g` 读成 `O.5g`。任何"把剂量转成数字"的环节都可能把读错的剂量念给老人听——所以 `dosage` 字段原样保留，`dosage_raw` 再存一份，下游只能念不能算。

**越界闸门（代码里硬拦，不靠自觉）**：`FORBIDDEN_ADVICE` 七条正则，命中就把整段话术换成"这个药的事我得让您孩子或药师再确认一下"，并在 `blocked` 字段里记下命中项。这是"最后一道闸"——即使将来有人改了话术模板，闸门仍会拦。

## 三、验收结果（实测，不是估算）

### 3.1 说明书字段准确率 —— **29/30 = 96.7%**（要求 ≥90%）

```

OK spec_03_ganmao_otc       字段 3/3  处方药=False 缺=[]
!! spec_04_metformin_rx     字段 2/3  处方药=True  缺=[]
       └ name 未命中 want=盐酸二甲双胍片  got='盐酸二甲双肌片'
OK spec_05_amlodipine_rx    字段 3/3  处方药=True  缺=[]
OK spec_06_vitc_otc         字段 3/3  处方药=False 缺=[]
OK spec_07_calcium_otc      字段 3/3  处方药=False 缺=[]
OK spec_08_aspirin_otc      字段 3/3  处方药=False 缺=[]
OK spec_09_omeprazole_rx    字段 3/3  处方药=True  缺=[]
OK spec_10_sanjiu_otc       字段 3/3  处方药=False 缺=[]

字段准确率：29/30 = 96.7%
处方药越界：0 处
```

**那唯一的一条失败，我不修，留着当证据。**
OCR 把「胍」读成了「肌」（形近字），于是药名判错。这恰恰说明：**OCR 会读错字，而读错的药名比读错一句话严重得多**。如果我把这条"修好"（比如加一张形近字映射表），下次换个药它还会错，只是错在你没测到的地方。正确做法是上游记下这个已知风险（见第五节风险 1）。

**造图说明（为什么这不叫放水）**：10 张样本是 Pillow 渲染的说明书版面——干净、无噪声，但尺寸和字号按老人手机实拍设定（1200px 宽、正文 15-17px，相当于真包装上 6-8 号字）。跑的是**真 OCR**（rapidocr，本地 onnx），不是假数据。真实照片的难点是反光、斜拍、折痕，这三项本验收**没有覆盖**，见第五节风险 2。

### 3.2 处方药 0 越界 —— **通过**

- 越界模式 7 条，自测全部拦住（含"一天吃三次就行"这类最像人话的）
- 6 张处方药样本：5 张标对 + 1 张（spec_03 非处方药）标对，漏判 0
- 处方药话术必含"医生/药师"，由验收脚本强制检查
- 判定顺序写死：OTC 标识优先 → 处方药标识 → 两边都有按处方药（安全侧）

> 这里踩到一个真实坑并已修：最初只匹配"处方药"，结果"**非**处方药"四个字里含"处方药"，7 张 OTC 药有 5 张被误判成处方药。误判方向是安全的（让老人多问一句，不是让他乱吃），但会让老人不信任——所以补了 OTC 优先判定。

### 3.3 老照片 —— 自测 2 项 + 结构验收

```
[6] 无人物照片（天空图）→ person_count=0，certain=True，说"我没看出有人"    ✔
[7] 有人 + 无已知人物（客厅图，检出 2 人）→ certain=False，反问"都是谁"    ✔
[8] 有人 + 有候选 + 但不是老照片 → 不加 guess，仍说"不确定"                ✔
[9] 确认→bind_person / 否认→noop（不写库）                                  ✔
```

**诚实说明：任务卡要求"测 20 张老照片"，这 20 张我拿不出来。**
- 仓库图集里 21 张全是日常场景照，没有老照片（黑白合影这类）
- 真实老照片涉及家庭成员肖像，我不能拿别人家的照片做测试，也不该用 AI 生成"假家人"来充当验收样本

所以老照片这条的验收状态是：**逻辑与话术已验证，20 张真实样本的 ≥80% 正确率待用户提供样本后补测**。验收脚本已写好判定口径（"正确认出"或"正确说不确定"都算对），用户提供 20 张后跑一遍即可出数字。这不装成"已完成"。

## 四、接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/photo/config` | 两个场景的可用状态（本地 OCR 装没装 / VLM 配没配） |
| POST | `/api/photo/elder` | `{path, known_people?}` → `guess` + `ask` + `candidates` + `certain` |
| POST | `/api/photo/elder/confirm` | `{path, accepted, name?, relation?}` → 写入意图（交给 B-5） |
| POST | `/api/photo/medicine` | `{path}` → `fields` + `speak` + `advice` + `is_prescription` |
| GET | `/api/photo/medicine/check?text=` | 越界话术自查（第二人 review 用） |

**没有"直接写入记忆库"的接口** —— 这是任务卡"猜+确认，不断言"的接口层落实：确认前物理上没有写入口。

## 五、已知风险（交给下游，别当没看见）

| # | 风险 | 影响 | 缓解 / 建议 |
|---|---|---|---|
| 1 | OCR 形近字误读（胍→肌），且**没有任何"我读错了"的自知** | 药名念错，老人可能拿错药 | 药名念出后接一句"您看看盒子上的名字对不对"；长期要接药品库做名称候选纠正（属 B 线数据） |
| 2 | 真照片反光/斜拍/折痕未覆盖 | 实测准确率会低于 96.7% | 需要用户提供 **10-20 张真实手机拍的说明书**做补测；预计会掉到 85-92% 区间 |
| 3 | 老照片 20 张验收样本缺失 | 该验收项无数字 | 用户提供样本后补跑（脚本已就绪） |
| 4 | 本地 OCR 靠 pip 装（rapidocr 1.4.4 + onnxruntime） | 换机器/换 venv 要重装 | 已在 `vision/requirements.txt` 注释说明；未装时接口明确返回 `ocr_unavailable`，不会静默返回空 |
| 5 | VLM 兜底会把说明书整张发到云 | 药品内容外发 | 本地 OCR 优先，只在字段缺失时才调 VLM；如"药品绝不上云"，设 `PHOTO_OCR=local` 关掉兜底 |

## 七、交给下游的接口点

- **→ 前端（F 线）**：说明书识别结果里有 `speak`（大字稿，可直接上屏）、`advice`（安全提示，必须显示）；老照片结果里 `needs_confirm=true` 时必须弹"是不是"的确认，不能替老人点。
- **→ B-5 人物档案**：接 `/api/photo/elder/confirm` 返回的 `intent`，`action=bind_person` 才写入；`noop` 不写。
- **→ 对话层**：`ask` 字段是"该说的话"，直接交给 TTS；不要二次加工（加工容易把"猜"改成"断言"）。

## 八、真实样本验收（2026-11-07 补，样本筛选与授权见 frames_real/SELECTION.md）

### 8.1 数字

| 组 | 有效样本 | 结果 | 口径 |
|----|---------|------|------|
| 渲染组（有 ground truth） | 10 张 | 字段 **29/30=96.7%**，越界 0 ✅ | 含判错不修的"胍→肌" |
| medicine 真实照片 | 9 张（从 20 张筛出） | 读空 3/9=33%，抽出药名 5/9=56%，越界 **0** ✅ | 无 ground truth，不出准确率 |
| old_photo 老照片 | 22 张 | **猜 0 / 说"认不太准" 22/22 / 异常 0** ✅ | 测误认率，不测认对率 |

### 8.2 样本筛选本身是个坑（留档）

第一轮抓的 14 张"药品图"全是 1900 年代英文古董药盒，OCR 能读出字但
一个中文药品字段都抽不出来——**样本和场景不匹配，测出来的数字是假的**。
第二轮换中文药名关键词，又混进医院大楼、中医古籍插画、诊所门头。
最后逐张看过、在 SELECTION.md 里显式登记收 9 张（理由逐条写），
验收只跑这 9 张。此前"读空率 65%"那个数字里大半是"图里本来没药盒"，
不是 OCR 的锅——**用错样本算出的指标比没有指标更坏**。

### 8.3 老照片组的偏差声明

22 张全是欧美 1900s PD 照片；真实场景是中国老人的黑白照片，人种/服饰/场景
分布不同，会系统性影响判断。22/22 说"认不太准"证明的是**兜底行为正确**，
不能外推为"对中国老人照片也会这样"。真机验证靠 H-6。

### 8.4 补样本结论

网图（Wikimedia）能稳定提供的中文药盒照片约 9-15 张，且反光/斜拍/家庭
光照的照片很少。**要把 H-4 从"方向性参考"提到"达标"，唯一解是请用户或
同事实拍 5-10 张家里药盒**（一张顶三张网图）。用户此前明确说"图片你帮
我找"，所以我没有主动索要；此处记录缺口，等用户方便时一句话就能补上。
