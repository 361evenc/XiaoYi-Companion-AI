## 三、真机会冒出四个新问题（模拟源没有的）

| # | 问题 | 模拟源为什么没有 | 预案 |
|---|---|---|---|
| 1 | **`weather` / `scene` 变成 unknown** | meta.json 里写死的 | 用 ⑤ 的 CLIP 零样本补（`clip_zeroshot.infer_environment()`）；或接天气 API |
| 2 | **分辨率不固定** | 我们 letterbox 到 1280×720 | `CameraSource` 里用 `CAP_PROP_FRAME_WIDTH/HEIGHT` 强制设定；但**不是所有相机都听话**，需实测 |
| 3 | **读帧会失败** | 文件永远读得到 | 已加连续失败计数 + `[WARN]`；失败不中断循环（`_fail_streak`） |
| 4 | **不释放就打不开** | 无此问题 | 已在退出时 `src.release()`；异常分支也要 release |

**第 2 条最容易被忽略**：很多 USB 摄像头只支持 640×480 / 1280×720 / 1920×1080 这几档，
你设 800×600 它可能默默给你 640×480。**真机接上第一件事：打印实际分辨率，别信你设的值。**

## 四、真机 Checklist（到货当天按顺序做）

### 硬件侧（这部分是"实体负责人"该担的）

- [ ] **摄像头选型**：优先 UVC 免驱（Linux 直接出 `/dev/video0`），分辨率 ≥1280×720，广角够不够看客厅
- [ ] **接口与线长**：USB 2.0 线超过 3 米会掉帧，需要带供电的延长线或换 USB 3.0
- [ ] **供电**：整机长期通电；**断电后必须能自己起来**（这是本条线的加分项）
- [ ] **安装位**：对着客厅/门口，避开逆光（对着窗户会拍成剪影，检测全废）
- [ ] **散热与防尘**：24 小时跑，外壳要留通风；镜头别对着油烟
- [ ] **固定**：防碰倒（老人家里容易碰）

### 软件侧（已就绪，只需验证）

- [ ] 跑 `perception_service.py --source camera` 看能不能持续出帧
- [ ] 打印实际分辨率，确认不是相机"降级"给的默认值
- [ ] 连续跑 6 小时，看有没有 `[WARN] 摄像头读帧失败`
- [ ] **拔插一次摄像头**，看程序是崩还是继续（当前行为：打 `[WARN]` 继续，但**不会自动重连**——这是已知短板）

### 已知短板（真机前必须补的两条）

1. **不会自动重连**：USB 掉了以后 `cap.read()` 一直 False，程序不崩但也永远不出帧。
   补法：连续失败 N 次后 `cap.release()` + 重新 `VideoCapture()`，退避重试。
2. **没有看门狗**：进程挂了没人拉起来。补法：Windows 计划任务开机自启 + 每 5 分钟检查进程。

> 这两条属于"长期运行保障"，清单里原本没有 —— 建议主动认领，答辩最好讲。
