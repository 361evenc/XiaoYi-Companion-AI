## 二、"读回确认 100%" 是怎么保证的

不是靠"记得要确认"，是靠**代码里根本没有另一条路**：

```python
def annotate(...):        # 只生成问句
    ...
    return {"ask": "...", "attempt": 1}      # 没有 write_intent 这个键

def confirm(self, accepted, ...):            # 唯一产出写入意图的地方
    if not accepted:
        return {"ok": True, "accepted": False, "ask_again": ...}   # 仍然不写
    intent = {"action": "upsert_object_location", ...}             # 只有这里
    return {"ok": True, "accepted": True, "write_intent": intent}
```

自测 `[1]` 直接断言 `"write_intent" not in annotate() 的返回`；`[2]` 断言否认时也没有 `write_intent`。

## 三、位置描述的粒度（这是最容易被做错的地方）

**YOLO 只给框，"框在画面哪个位置" ≠ "东西在房间哪个位置"。** 摄像头装在哪、朝哪，决定了同一个框可能对应完完全全不同的屋子位置。所以：

| 做的 | 不做的 |
|---|---|
| 找画面里最大的家具当锚点（桌/柜/床/沙发…） | 不推测房间结构 |
| 九宫格 → "画面上半偏左 / 正当中 / 下半偏右" | **不用"左上角"**（老人心里的"角"是房间的角，不是画面的角） |
| 话术用"…那一片""看着像在…上" | 不说"就在抽屉第二层"（做不到） |
| 无锚点 → 退化说"画面中间那一带" | 不硬编一个家具名 |

实跑示例（`frames/20_kitchen_dining.jpg`）：

```
"药箱在厨房桌子那一片（画面下半偏左），对吧？"
```

**"10 件物品跑通"的"对"要按这个粒度判**——我把判定标准写在这里，是为了将来验收时不会被人用"没说清在第几层"来打回，也不会被我自己用"大致对"糊过去。

## 四、超 2 次的处理

任务卡原文："否认→重新标注（最多 2 次，仍不行就说'这次我没看懂，您再跟我说一遍'）"。

实现细节上有个坑：如果只在 `annotate()` 里计数，老人换个物品名又从头算，等于无限循环。所以会话按**物品名**绑定：
- 同一物品名第 3 次 → 返回 `gave_up` + 任务卡原话，**并清空会话**
- 换物品名 → 重新从第 1 次算（这是对的，说的是另一个东西）

## 五、附带做的：轨迹观测位（给 B-2 spike 的第①项打底）

任务卡 B-2 的 spike 要测"动作识别（放置/拿走）准确率 ≥70%"，但 H-2 的持续录制只存结构化条目，没有"这个东西被拿走了"的判定。我在本文件里附带了一个 `Trajectory` 观测位：

```python
tr.observe("眼镜@床头", present=True)    # 每一拍喂一次"还在原位吗"
tr.detect_events("眼镜@床头")
# → [{"type": "taken", ...}, {"type": "placed", ...}]
```

**这只解决"判定器有没有"，不解决"准确率是多少"**——spike 要 50 个真实事件样本，得真人摆东西、真人拍。别把这段当成 spike 已完成。

## 七、B-2 落地后要接的三件事（给后端线）

1. **写入**：调 `confirm(True)["write_intent"]` → `POST /api/spatial`（B-2 的 upsert）。字段对不上就改 `confirm()` 的输出，采集侧不用动。
2. **`source` 区分**：写入意图里 `source="voice_annotate"`，与 H-2 持续感知产出区分（T-2 溯源要求）。B-3 找物回答时，"您跟我说过"和"我最后见着"要用不同话术。
3. **`confidence=0.9`**：老人亲口确认的位置，置信度高于 YOLO 自动检测（后者按 B-2 的高置信线 0.8）。这不是拍脑袋——老人口述的位置错了，是老人自己记错；YOLO 错了是模型错。两者的错误率不是一个量级。
