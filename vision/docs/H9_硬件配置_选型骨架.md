## 三、语音响应毫秒预算（H-9 唯一必须实测的项）

任务卡原话："语音响应要有明确毫秒预算（不说'零延迟'这种非工程语言——老人感觉'卡'的阈值是实测出来的，不是拍脑袋的）。"

### 3.1 已实测（今天跑的，3 轮）

| 环节 | 实测值 | 说明 |
|---|---|---|
| 本地 YOLO 单帧（CPU） | **27-57ms**（首帧 2.7s=模型加载） | 空白帧；真实画面（检出多目标）会更高，历史 `world_perception` 记录在 60-100ms |
| LLM 完整回复（DeepSeek，非流式，20 tokens） | **1017-1404ms** | 这是"发出去→收完"，**不是首字延迟**。改流式后首字会显著降低 |

### 3.2 测不出来的（诚实留白）

| 环节 | 为什么测不出来 | 怎么补 |
|---|---|---|
| ASR（老人说完 → 文字） | 本机 `local_secrets.json` 里只有 `VOLC_APP_ID` / `VOLC_ACCESS_TOKEN`，**ASR 凭据缺失** | H-6 实测现场采集（10 次取中位） |
| TTS（文字 → 第一个音频包） | 同上，TTS 凭据缺失 | 同上 |

### 3.3 预算表（缺项留空，不编数字）

```
asr                 = 待测
llm                 = 1017ms（非流式上限；流式首字待测）
tts                 = 待测
play_start          = 待测
vision_optional     = 27ms（不影响主链路，异步）
target_total        = 待测 ★
```

### 3.4 `target_total` 怎么定（方法，不是数字）

让老人自己说"卡不卡"：20 次对话，每次随机注入 200 / 400 / 600 / 800ms 额外延迟，每次结束问一句"刚才是不是卡了一下"。

- 老人说"没感觉"的最长延迟 → 就是目标总时长
- **为什么不让工程拍 800ms**：老人对"卡"的感知受语速、内容熟悉度影响很大，数字只能从老人嘴里出来
