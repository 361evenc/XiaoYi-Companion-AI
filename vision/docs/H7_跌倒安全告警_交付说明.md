## 一、这一卡的口径：宁可误报，不可漏报

任务卡 v3 有明确的原则修正，抄原文：

> 跌倒检测的正确原则 = **宁可误报让人确认，不可漏报**——漏报真跌倒=生命风险；
> 误报=一次虚惊，有确认流程兜着（误报成本可控，漏报成本无限）。

所以本卡所有取舍都朝保召回偏。**最反直觉的一点是：我没有靠"提高阈值"来压误报。**

---

## 二、检测怎么做（以及为什么必须两个条件）

YOLOv8n 的 80 类里**没有 fall / lying / slip 任何相关类别**（已实际查过 `model.names`）。
所以"检测跌倒"只能从 `person` 框的几何特征推：

```
① 宽高比 ≥ 1.15          —— 框变横（人直立时约 0.35-0.6）
② 框顶比例 ≥ 0.72 且 框底比例 ≥ 0.92  —— 头已经低到地面附近
```

### 第二条为什么不能省（这是本卡最值钱的一次实测）

我用真实素材 `frames/17_living_window.jpg`（两人并排躺在沙发上看书）跑了一遍：

```
person 框 = [338, 357, 964, 715]  →  宽高比 1.75
```

**只看宽高比，这张图会直接触发跌倒告警。** 而它是再正常不过的活动。

加上"框顶必须高过 0.72（头到了地面高度）"之后：
- 这张图框顶 = 357/720 = **0.50** → 不报 ✅
- 真倒地的人框顶 0.6-0.9、框底贴地 → 报 ✅

这条已经写成回归用例 `并躺看书大横框不误报（真实素材回归）`，
以后谁想"简化成只看宽高比"，测试会立刻挂。

### 连续 2 拍确认，不是提高阈值

单帧 YOLO 误检很常见。1 拍就报 → 月误报率顶天 → 被迫调高阈值 → **反而杀召回**。
用"时间持续性"（2 拍内都在地上，6 秒窗口）代替"提高置信度阈值"压误报，
这是保召回原则下唯一正确的做法。倒地后自己站起来 → 立即取消，不追问。

## 三、三段响应（任务卡写死，一条不改）

| 老人反应 | 处理 | 话术 |
|---|---|---|
| 说"没事" | 归档为误报，计入统计（供阈值调参） | — |
| 说"起不来/帮忙/疼" | **立即转报子女 + 提示 120** | 我已经给您孩子打了，着急的事您自己按120 |
| 60s 无应答（中途追问 1 次） | **直接转报子女 + 提示 120** | 同上 |

**两个关键判断顺序（都朝保召回偏）：**

1. **先判"求助"再判"没事"** —— "我没事但是起不来"必须算求助。宁可多报。
2. **听不懂的应答不当作"没事"** —— 老人说"嗯……"、或者 ASR 识别错了，
   一律记为 `unclear`，继续等超时。把听不懂当没事 = 漏报。

**不自主拨 120**：MVP 电脑拨号做不到，话术写诚实，不假装能打。
**不做医疗判断**：只问"您没事吧"、只转达。话术常量可被
`check_medical_wording()` 直接校验（第二人 review 用）。

## 六、已知限制（诚实列出）

1. **地滑没有单独检测**。卡上写"地滑/跌倒"，但 YOLO 没有"地面湿滑"这个类别。
   本卡实际做的是**跌倒**（人倒地）；地滑只能靠人倒下来间接反映。
   真要做地滑需要额外的地面状态识别模型，不在本卡范围。
2. **几何规则的天花板**：蹲下捡东西（宽高比可能 > 1.15）如果恰好框顶也低于 0.72，
   会误报。改法是接姿态估计（关键点判断"头是否低于髋"），但会增加依赖和算力。
   **当前选择：接受少量误报，用确认流程兜住** —— 这正是任务卡的原则。
3. **单人在画面才有意义**。多人场景取置信度最高的人，可能选错对象。
4. **摄像头必须能看到地面**。放桌面朝上的角度拍不到地面，检测等于失效。
5. **未做 24h 连续观察**，只做了 21 张图集回归。
6. **后端接口未端到端联调**（本机 venv 无 fastapi，只做语法校验）。
